## **Документация по проекту Agile-бота**

---

### **1. Общее описание проекта**

Telegram-бот предназначен для взаимодействия с пользователями, предоставления информации о чае, управления профилями пользователей и выдачи достижений. Бот интегрирован с базой данных PostgreSQL и поддерживает команды для администраторов, модераторов и обычных пользователей.

Запуск в режиме разработки:

```bash
    watchmedo auto-restart --directory=. --pattern="\*.py" -- python bot.py
```

Запуск в docker:

```bash
   cd ./
   docker-compose up --build
```

---

### **2. Структура проекта**

Проект состоит из нескольких файлов, каждый из которых выполняет определенные функции:

#### **2.1. Файл `bot.py`** - основной файл бота, содержащий обработчики команд и колбэков

**Назначение:** основной файл бота, который управляет всеми командами и взаимодействиями с пользователем. Содержит обработчики команд и колбэков.

**Описание функциональности**:

- **работа с базой данных**: бот подключается к PostgreSQL для хранения данных пользователей, их предпочтений и достижений. Используются таблицы: users, unique_users, users_all_data_card_tea, bot_content.
- **обработка команд**: каждая команда обрабатывается отдельным обработчиком, который вызывает соответствующую функцию из модуля commands или admin_commands.
- **обработка колбэков**: колбэки от кнопок обрабатываются в функции handle_callback_query, где происходит обновление данных пользователя или выполнение других действий.
- **логирование**: все действия бота логируются для отслеживания ошибок и анализа работы.
- **повторные попытки подключения**: в случае ошибок подключения к базе данных или API Telegram бот предпринимает несколько попыток переподключения.

**Основные функции:**

- **`handle_start`**: Обработчик команды `/start`. Запускает бота и отправляет приветственное сообщение.
- **`handle_new_tea`**: Обработчик команды `/new_tea`. Отправляет клавиатуру для выбора чая.
- **`handle_help`**: Обработчик команды `/help`. Отправляет справку по использованию бота.
- **`handle_callback_query`**: Обработчик колбэков. Обрабатывает нажатия на кнопки и обновляет данные пользователя.
- **`start_polling`**: Запускает бота с повторными попытками подключения в случае ошибок.

##### **2.2. Файл `utils.py`** - вспомогательные функции для работы с базой данных, логирования и проверки прав доступа

###### **Назначение:** содержит вспомогательные функции для работы с базой данных, проверки прав доступа и логирования. Файл содержит вспомогательные функции и настройки, которые используются в других частях бота.

##### **Основные функции:**

- **`get_current_date`**: Возвращает текущую дату в формате `ГГГГ-ММ-ДД`.
- **`is_allowed_user`**: Проверяет, имеет ли пользователь права администратора или модератора.
- **`open_connection`**: Открывает соединение с базой данных.
- **`close_connection`**: Закрывает соединение с базой данных.

##### **Пример использования:**

```python
date = get_current_date() # Возвращает текущую дату, например, 2023-10-15.

get_current_date: # Возвращает текущую дату в формате ГГГГ-ММ-ДД. Используется для записи даты в базу данных.

open_connection: # Открывает соединение с базой данных PostgreSQL. В случае ошибки подключения логирует ошибку и возбуждает исключение.
```

##### **2.3. Файл `message_utils.py`** - функции для управления сообщениями (удаление, сохранение идентификаторов)

###### **Назначение:** cодержит функции для управления идентификаторами сообщений и их удаления. Файл содержит функции для управления идентификаторами сообщений и их удаления.

###### **Основные функции:**

- **`try_delete_message`**: Пытается удалить сообщение бота в указанном чате по типу сообщения.
- **`save_message_id`**: Сохраняет идентификатор сообщения в словаре `message_ids`.
- **`try_delete_message`**: Пытается удалить сообщение бота в указанном чате по типу сообщения. Если сообщение уже удалено или не найдено, логируется предупреждение. В случае других ошибок логируется ошибка.
- **`save_message_id`**: Сохраняет идентификатор сообщения в словаре message_ids. Используется для отслеживания сообщений, которые могут быть удалены позже.

###### **Пример использования:**

```python
try_delete_message(bot, chat_id, 'command') # Удаляет сообщение с типом 'command' в указанном чате.

save_message_id(chat_id, 'command', message_id) # Сохраняет идентификатор сообщения в словаре.
```

##### **5. Файл `commands.py`** - команды, доступные всем пользователям.

#### **Описание таблиц базы данных**

База данных PostgreSQL содержит несколько таблиц, которые используются для хранения данных о пользователях, чае, достижениях и других сущностях. Ниже приведено описание каждой таблицы.

##### **1. Таблица `users`**

- **Назначение:** Хранит данные о пользователях, включая их выбор чая.
- **Поля:**
    - `user_id` (INT): Уникальный идентификатор пользователя.
    - `username` (TEXT): Имя пользователя.
    - `date` (DATE): Дата записи.
    - `select_tea` (INT): ID выбранного чая.
    - `age` (INT): Возраст пользователя.
    - `gender` (TEXT): Пол пользователя.



##### **2. Таблица `unique_users`**

- **Назначение:** Хранит уникальные данные о пользователях, включая их достижения и счетчики.
- **Поля:**
    - `user_id` (INT): Уникальный идентификатор пользователя.
    - `username` (TEXT): Имя пользователя.
    - `date_start` (DATE): Дата первой записи.
    - `date_last` (DATE): Дата последней записи.
    - `age` (TEXT): Возраст пользователя.
    - `gender` (TEXT): Пол пользователя.
    - `evaluation` (INT): Оценка чай-бота.
    - `count_select_tea` (INT): Количество выборов чая.
    - `count_achievements` (INT): Количество достижений.

##### **3. Таблица `user_achievements`**

- **Назначение:** Хранит данные о достижениях пользователей.
- **Поля:**
    - `user_achievement_id` (SERIAL): Уникальный идентификатор записи.
    - `user_id` (INT): Уникальный идентификатор пользователя.
    - `achievement_id` (INT): ID достижения.
    - `date_achieved` (DATE): Дата получения достижения.

  ##### **4. Таблица `achievements`**

- **Назначение:** Хранит информацию о доступных достижениях.
- **Поля:**
    - `achievement_id` (SERIAL): Уникальный идентификатор достижения.
    - `achievement_name` (TEXT): Название достижения.
    - `description` (TEXT): Описание достижения.
    - `condition` (TEXT): Условие для получения достижения.
    - `image_achievements` (BYTE(HEX)): Ссылка на изображение достижения.

##### **5. Таблица `bot_content`**

- **Назначение:** Хранит информацию о чае, включая текст, изображения и ссылки.
- **Поля:**
    - `id` (SERIAL): Уникальный идентификатор записи.
    - `content` (TEXT): Текст о чае.
    - `image` (BYTE(HEX)): Ссылка на изображение.
    - `tea_name` (TEXT): Название чая.
    - `quote_agile` (TEXT): Цитата, связанная с Agile.
    - `question` (TEXT): Вопрос для пользователя.
    - `link` (TEXT): Ссылка на дополнительную информацию.

#### **Код создания таблиц**

Ниже приведен SQL-код для создания таблиц в базе данных PostgreSQL.

```sql
-- Таблица users

CREATE TABLE users (
    user_id INT PRIMARY KEY,
    username TEXT,
    date DATE,
    select_tea INT,
    age INT,
    gender TEXT
);

-- Таблица unique_users
CREATE TABLE unique_users (
    user_id INT PRIMARY KEY,
    username TEXT,
    date_start DATE,
    date_last DATE,
    age TEXT,
    gender TEXT,
    evaluation INT,
    count_select_tea INT,
    count_achievements INT
);

-- Таблица user_achievements
CREATE TABLE user_achievements (
    user_achievement_id SERIAL PRIMARY KEY,
    user_id INT REFERENCES unique_users(user_id),
    achievement_id INT,
    date_achieved DATE
);

-- Таблица achievements
CREATE TABLE achievements (
    achievement_id SERIAL PRIMARY KEY,
    achievement_name TEXT,
    description TEXT,
    condition TEXT,
    image_achievements TEXT
);

-- Таблица bot_content
CREATE TABLE bot_content (
    id SERIAL PRIMARY KEY,
    content TEXT,
    image TEXT,
    tea_name TEXT,
    quote_agile TEXT,
    question TEXT,
    link TEXT
);
```

#### **Связи между таблицами**

1. **`users` и `unique_users`:**
      - Поле `user_id` в таблице `users` связано с полем `user_id` в таблице `unique_users`.
      - Это позволяет синхронизировать данные о пользователях.

2. **`unique_users` и `user_achievements`:**
      - Поле `user_id` в таблице `unique_users` связано с полем `user_id` в таблице `user_achievements`.
      - Это позволяет отслеживать достижения каждого пользователя.

3. **`users` и `bot_content`:**
      - Поле `select_tea` в таблице `users` связано с полем `id` в таблице `bot_content`.
      - Это позволяет хранить информацию о выбранном чае.

4. **`achievements` и `user_achievements`:**
      - Поле `achievement_id` в таблице `user_achievements` связано с полем `achievement_id` в таблице `achievements`.
      - Это позволяет сохранить связь между достижением и его описанием.
